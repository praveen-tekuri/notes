## 1. Introduction

- To create a server we use Express, which makes work much easier compared to building a server in pure node JS.

- Express is a web application framework for nodeJS
    - It provides set of features for building web applications and APIs.
    - It simplifies building server-side applications with an easy to use API for routing, middleware, and handling HTTP requests and responses.

## 2. Creating a Server

- `npm i express` installs express 

    ```js
    const express = require("express"); // importing the express

    const app = express(); // initialize the app

    // Request handler
    app.use((req, res) => {
        res.send("Hello from the server !!");
    })

    // Server is listening on port 3000
    app.listen(3000, () => {
        console.log("Server is successfully listening on port 3000...");
    });

    ```
- RUN CODE using command node app.js in terminal, then go to http://localhost:3000 in your browser you will 
   see "Hello from the server !!!" displayed.
  
- Server is listening on port 3000, and the server is responding to the incoming request.
 
- So our server is running on port 3000, and the browser is making request to localhost 3000 and my server is responding
  "Hello from the server!!!"

## 3. Avoiding const restarts with nodemon

- Nodemon automatically refresh the server, whenever we make changes
- ⚠️ NOTE: Once any package is installed globally, we don't need to install it again for another project. check in terminal nodemon -v.

    ```json
    "scripts": {

    }
    ```

## 4. Routing and Request handlers

- `app.use("/", (req, res) => {...});` - This route overrides everything else. any route that matches `"/"` or starts with `"/"` will be handled by this route. it acts like a wildcard. so it does not just cover `"/hello"`, it also handles anything like `"/hello/q21/321"`
- ⚠️ Just by changing the order of code, a lot of things can change

    ```js
    app.use("/hello", (req, res) => {
        res.send("hello hello hello");
    });

    app.use("/hello/2", (req, res) => {
        res.send("hello 2");
    });

    // localhost:7777/hello/2 -> hello hello hello 

    /*
    When a request comes in, express checks routes in order it matches the first route that fits, 
    then execute it's handler So "/hello" matches before "/hello/2" in this order.
    BUT if i reverse the order everything works as expected.
    */

    app.use("/hello/2", (req, res) => {
        res.send("hello 2");
    });

    app.use("/hello", (req, res) => {
        res.send("hello hello hello");
    });

    // localhost:7777/hello/2 -> hello 2
    // localhost:7777/hello -> hello hello hello 

    // - SO, Order of routes matters.
    // - The order in which you write routes is very important in express
    // - Routes are matched top to bottom, and first match is executed
    ```

## 5. HTTP methods

- HTTP methods define the type of action a client wants to perform on a resource identified by a URL. these methods are fundamental to how web browsers and applications interact with web servers and APIs. 
- The most commonly used methods include: GET, POST, PUT, PATCH, and DELETE
- When you visit a server via web browser, it sends a GET request by default. to make POST requests browsers are not ideal for testing APIs. So we can use POSTMAN.
- Postman is an indian-origin global software company that offers an API platform for developers to design, build, test and collaborate on APIs.
- Testing API in postman
    - Choose the type of request: GET, POST, PATCH etc,.
    - GET request to the URL: http://localhost:7777/hello => "hello hello hello".
    - POST call to the same URL: http://localhost:7777/hello => "hello hello hello".
    - It's giving same output as GET method above. that's because "app.use()" matches all http methods(GET, POST, PUT, DELETE etc,.)
    - BUT ideally, if you make GET call to "/profile", it should return the user's profile data. and if you make a POST call to "/profile", it should add or update the profile data. SO how do we handle that? By using method-specific handlers like app.get() and app.post() instead of app.use().
    - `app.use()` matches every http method while `app.get()` handles only `GET request`.
    - Each route responds differently based on the HTTP method(GET, PUT, POST, DELETE) and that's how real APIs separate fetching, creating, and deleting operations.
- ⚠️ Always place your specific routes before the generic one.
    ```js
    app.get()
    app.post()
    app.delete()
    app.use() // keep this generic one last

    The order in which you define routes in express directly affects which one gets
    executed. express matches routes from top to bottom & stops at the first match.
    ```
## 6. Advanced Routing in Express
> 1. Query Parameters
- Suppose you have a URL like `http:localhost:7777/user?userId = 101`, if you make a call to it, how can you get the userID inside your route handler? USE `req.query` (gives you all the query Parameters)
    ```js
    app.get("/user", (req, res) => {
        console.log(req.query);
        res.send({firstName: 'praveen', lastName: 'tekuri'})
    });

    // Make an API call in postman, check terminal you will see the query Params {userId: 101}
    ```
> 2. Dynamic Routes
- If you have URL like `http:localhost:7777/user/707` you can handle it using route Parameters.
    ```js
    app.get("/user/:userId", (req, res) => {
        console.log(req.params);
        res.send({firstName: 'praveen', lastName: 'tekuri'})
    });

    // Make an API call, check terminal, you will see {userId: 707}
    ```
- ➡️ More complex routes using multiple Parameters

    ```js
    app.get("/user/:userId/:name/:password", (req, res) => {
        console.log(req.params);
        res.send({firstName: 'praveen', lastName: 'tekuri'})
    });

    // make an API call, check terminal. 
    // http://localhost:7777/user/:userId/:praveen/:password => { userId: ':userId', name: ':praveen', password: ':password' }
    ```

## 7. Middleware and Error handlers

> 1. Multiple route handlers

- `next()` is callback function used in middleware to pass control to the next function, in the request to response processing cycle. it's core mechanism of how express handles incoming requests, allowing middleware functions to work together and form a chain of operations.
- Every middleware function in express receives 3 main arguments. `function(req, res, next){...}`
    - `req`: the request object, representing the incoming data from the client.
    - `res`: the response object, used to send data back to the client.
    - `next`: a function that, when called, passes control to the next middleware in the stack.
if the middleware function does not call the next() and does not end the response (e.g, by using res.send() OR res.json()) the request will hang indefinitely, as express will not know how to proceed to the next step.
    ```js
    const express = require("express"); // importing the express

    const app = express(); // initialize the app

    app.use((req, res, next) => {
        console.log("middleware1: logging request")
        next(); // passes control to the next middleware 
    });

    app.use((req, res, next) => {
        console.log("middleware2: time check");
        req.requestTime = Date.now();
        next();
    });

    app.get("/", (req, res) => {
        res.send("Hello world: Request at: " + req.requestTime);
    });

    // http://localhost:7777/ -> Hello world: Request at: 1762066705219
    // 1. middleware1 runs first and logs a message
    // 2. next() allows the 2nd middleware to run 
    // 3. middleware2 adds a timestamp and calls next()
    // 4. Finally, the route handler sends a response
    ```
- Variations of next()
    - `next()` - moves to the next middleware function
    - `next("route")` - Skips the remaining middleware of current route and moves to the next matching route handler.
    - `next(err)` - passes an error to express's built-in error handling middleware, triggering a server response(usually with error code)
    - One route can also have Multiple route handlers using the `next()`:

    ```js
    app.use("/user", (req, res, next) => {
        console.log("handling the route user 1");
        res.send("response 1");
        next();
    },(req, res, next) => {
        console.log("handling the route user 2");
        // res.send("response 2");
        next();
    },(req, res, next) => {
        console.log("handling the route user 3");
        // res.send("response 3");
        next();
    }, (req, res, next) => {
        console.log("handling the route user 4");
        // res.send("response 4");
        next(); // Can't GET user, as there's no next function to execute.
    })

    // - if you don't send the response back res.send(), it will be hanging
    // - app.use() can handle any type of http methods(GET, POST, DELETE etc,.)
    // - Order of routes matters a lot.
    // - app.use("/route", rH1, rH2, rH3, rH4)
    ```
> 2. Middlewares

- Express is a routing and middleware web framework that has minimal functionality of its own. an express application is essentially a series of middleware function calls.
- Middleware functions are functions that have access to the request object(req), the response object(req) and the next middleware function in the applications request-response cycle. the next middleware function is commonly denoted by variable named "next"
- Middleware function can perform:
    - Execute any code
    - Make changes to the request and response objects
    - End the request-response cycle
    - Call the next middleware function in the stack.
    - If the current middleware function does not end the request-response cycle, it must call next() to pass control to next middleware function, otherwise, the request will be left hanging.
    ```js
    // 1. Middlewares
    // Handle auth Middlewares for all GET, POST, ... requests

    // Admin Middleware
    app.use("/admin", (req, res, next) => {
        console.log("Admin auth is getting checked");
        const token = "xyz";
        const isAdminAuthorized = token === "xyz";
        if(!isAdminAuthorized){
            res.status(401).send("Unauthorized request");
        }else{
            next();
        }
    });

    // User Middleware
    const userAuth = (req, res, next) => {
        console.log("User authentication is getting checked");
        const token = "xyz";
        const isUserAuthorized = token === "xyz";
        if(!isUserAuthorized){
            res.status(401).send("Unauthorized request");
        }else{
            next();
        }
    };

    // For login we don't require Middleware, or authentication
    app.get("/user/login", (req, res) => {
        res.send("User logged in successfully");
    });

    // Whenever /user/data request will come, it will first go to userAuth Middleware
    // then check the condition then do the follow
    app.get("/user/data", userAuth, (req, res) => {
        res.send("user data sent")
    });

    app.get("/admin/getAllData/", (req,res) => {
        res.send("all data sent")
    });

    app.get("/admin/deleteUser", (req, res) => {
        res.send("Deleted User");
    })

    // Express takes and matches all the routes, and goes through the Middlewares one after another,
    // Finally it goes till one after other, till it sends the response back. the only job of express
    // is to take request and give response as soon as possible. and it goes in order to keep checking 
    // these functions.
    ```

> 3. Error Handling

- try-catch OR wildCard

    ```js
    // try-catch
    app.get("/getUserData", (req, res) => {
        try{
            // LOGIC of DB call and get user getUserData
            res.send("User Data sent");
        }catch(err){
            res.status(500).send("Some error contact support team");
        }
    })

    // wildCard
    // Always keep these towards the last of your application, so if anything will breaks, it will caught here.
    app.use("/", (err, req, res, next) => {
        if(err){
            res.status(500).send("Something went wrong");
        }
    })
    ```

- ⚠️ Parameter order matters a lot
    - app.use("/", (req, res))
    - app.use("/", (req, res, next))
    - app.use("/", (err, req, res, next))
